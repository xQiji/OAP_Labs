Лабораторна робота №4: Клієнт-серверна взаємодія та API

Цей проєкт демонструє повноцінну інтеграцію між Frontend та Backend частинами веб-додатка з використанням REST API, централізованою обробкою станів та помилок.



Основні реалізовані вимоги (Features)

1\. Архітектура та Взаємодія

Роздільний запуск: Frontend (HTML/JS/CSS) та Backend (Node.js/TypeScript) працюють на різних портах.



Взаємодія через API: Фронтенд не містить "зашитих" даних, уся інформація динамічно підтягується з бекенду через fetch.



Єдиний API-клієнт: Усі мережеві запити винесені в окремий "тонкий" модуль apiClient.js. Компоненти UI не роблять запити напряму, а викликають методи клієнта (наприклад, getTickets(), createTicket(), deleteTicket()).



2\. CRUD Операції

Реалізовано повноцінну роботу з основною сутністю (Tickets):



Отримання списку заявок (GET /api/tickets)



Створення нової заявки (POST /api/tickets)



Видалення заявки (DELETE /api/tickets/:id)



3\. Керування станами інтерфейсу (UI States)

Інтерфейс користувача продуманий і реагує на всі етапи взаємодії з сервером. Реалізовано стани:



Loading: Відображення індикатора/тексту "Завантаження..." під час очікування відповіді від сервера.



Success: Коректне відображення таблиці з даними після успішного запиту.



Empty: Спеціальне повідомлення "Немає даних", якщо база даних порожня.



Error: У разі падіння сервера або помилки мережі користувач бачить зрозуміле повідомлення про помилку (без ефекту "білого екрану").



4\. Валідація та Обробка помилок

Клієнтська валідація: Перевірка обов'язкових полів перед відправкою запиту на сервер (захист від "фантомних" запитів).



Серверна валідація: Перевірка вхідних DTO на бекенді.



Узгоджений формат помилок: Усі HTTP-помилки (400, 401, 403, 404, 500) повертаються з бекенду в єдиному централізованому форматі { code, message } (реалізовано через клас ApiError та глобальний middleware). Фронтенд коректно їх зчитує та показує користувачу.



5\. CORS та Мережева безпека

Налаштовано CORS без використання небезпечного \*. Явно вказано дозволений origin фронтенду (наприклад, http://127.0.0.1:5500), дозволені методи (GET, POST, PUT, DELETE, OPTIONS) та заголовки.



Технологічний стек

Бекенд: Node.js, Express, TypeScript, SQLite (better-sqlite3).



Фронтенд: Vanilla HTML, CSS, JavaScript (ES6 Modules).



Як запустити проєкт

Крок 1: Запуск Backend



Перейдіть у папку бекенду.



Встановіть залежності: npm install



Запустіть сервер: npm run start (або npm run dev)

Сервер запуститься на порту (наприклад, 3000).



Крок 2: Запуск Frontend



Відкрийте папку з фронтендом у VS Code.



Запустіть сторінку через Live Server (або інший локальний сервер).



Переконайтеся, що порт фронтенду (наприклад, 5500) збігається з дозволеним у налаштуваннях CORS на бекенді.
